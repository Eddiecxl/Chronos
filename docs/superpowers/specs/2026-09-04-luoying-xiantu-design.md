# 《落樱仙途》Chronos 集成设计

日期：2026-09-04

## 目标

用用户提供的 `落仙v2.html` 替换 Chronos 的 `/chronos/game` 旧游戏，并把它完善为可长期游玩的中文修仙文字游戏。

游戏必须同时具备两种能力：

- 不依赖网络或模型的完整本地游戏，从开局到多结局都能正常游玩。
- 可随时开启、关闭或切换的 AI 叙事增强，支持现有提供商，并重点支持 Groq 与 Google Gemini。

现有粉色樱花、水墨山景、自由文字输入、顶部状态栏、快捷指令、三槽存档和游戏内 AI 设置是产品识别度的一部分，集成时保持整体视觉和操作方式，不重做成 Chronos 原有的深色 Rift 风格。

## 非目标

- 不改造 Chronos 的账号、计划、好友、房间、小说或 PL-900 功能。
- 不引入多人联机、付费系统、排行榜或服务端云存档。
- 不要求玩家在电脑上部署本地大模型。
- 不把第三方 API Key 写入前端构建产物、Git 仓库或游戏存档。

## 方案选择

### 采用：独立同源游戏模块

游戏作为 `public/luoying-xiantu/` 下的独立静态模块运行，由 `/chronos/game` 页面通过同源 iframe 承载。Chronos 负责路由、登录边界和导航；游戏模块负责全部界面、状态、存档与叙事。

此方案能最大程度保留原始 HTML 的视觉和交互，并隔离游戏 CSS，避免它的全局 `body`、按钮和动画样式污染 Chronos。游戏仍与 Chronos 同源，因此可安全读取当前登录会话令牌并访问受保护的 AI 代理接口。

### 未采用：完全改写为 React

React 改写能让组件更统一，但会增加迁移风险和工作量，也更容易改变原始 UI。当前游戏已经有完整的 DOM 驱动交互，改写带来的收益不足以抵消风险。

### 未采用：直接把单文件 HTML 粘进 Chronos 组件

此方案短期最快，但全局样式、事件监听和存档生命周期会与 Chronos 相互干扰，后续内容维护也会继续集中在一个超大文件中。

## Chronos 集成

- `src/ChronosRiftGame.jsx` 替换为轻量游戏宿主，渲染同源 iframe。
- `src/game.css` 改为宿主布局样式，使游戏在桌面和手机端尽量占满可用视口。
- 桌面导航继续使用 `Game` 路由名称，移动导航的副标题从 `Rift` 改为 `落樱仙途`。
- iframe 使用清晰标题和受控权限；不授予摄像头、麦克风、定位等无关权限。
- 游戏离开页面后保留本地状态，再次进入时可继续前世。

## 游戏结构

本地内容采用“章节骨架 + 状态机 + 随机事件池”。AI 可以扩展章节之间的过程，但不能绕过核心状态验证或直接写入任意存档字段。

### 五幕主线

1. **尘缘初醒**：柴房开局、赵氏欺压、初识林小满与李老、获得引气法、进入宗门。
2. **外门风云**：日常委托、坊市、炼丹、宗门大比、同门关系与第一次重大抉择。
3. **筑基秘境**：组队探索、遗迹机关、传承争夺、魔修暗线，以及可永久改变关系的选择。
4. **金丹劫火**：宗门危机、仙魔阵营、身世揭露、重要角色个人线和世界状态变化。
5. **问天渡劫**：心魔、因果清算、最终敌手、飞升或留世，并根据长期选择进入不同结局。

### 可玩系统

- 境界与修为：炼气至渡劫，突破带条件、风险和专属事件。
- 战斗：普通攻击、功法技能、防御、道具、逃跑、状态效果和敌人意图提示。
- 地图：宗门、后山、坊市、洞府、城镇、秘境等地点，地点随章节解锁。
- 任务日志：主线、支线与日常委托，显示目标、进度和奖励。
- 物品与装备：丹药、材料、武器、护具、任务物品和关键传承。
- 炼丹与修炼：消耗材料、成功率、品质和阶段性修炼事件。
- 人物关系：主要 NPC 的好感、信任或敌意，以及个人事件和结局影响。
- 因果与倾向：善恶不是单一分数，而由关键因果旗标与有限倾向值共同决定。
- 随机奇遇：按地点、境界、章节和已发生事件筛选，避免不合时宜的重复事件。
- 成就与图鉴：记录重要选择、结局、人物和已发现内容。
- 多结局与再世：飞升、守界、归隐、魔道、陨落等结局；通关后可保留图鉴与部分传承开启再世。

## 输入与叙事

玩家继续通过一个输入框说话或行动。输入处理按以下顺序执行：

1. 识别明确的本地指令，例如修炼、移动、战斗、使用物品、查看任务与存档。
2. 当前剧情若处于选择、对话、战斗或命名等待状态，优先交给对应状态处理器。
3. AI 已启用时，把自由输入连同压缩后的世界状态和近期上下文交给所选模型。
4. AI 未启用或调用失败时，由本地意图解析与场景反应库处理，保证故事继续。

AI 输出只允许有限的叙事块、选项建议和受控效果。所有数值、物品、任务、地点和关系变化都经过本地校验、上下限限制及白名单过滤。

## AI 提供商与切换

游戏设置保留以下选择：

- 本地命运线
- Puter.js
- Google Gemini
- SiliconFlow
- OpenRouter
- Groq
- 自定义 OpenAI 兼容接口

设置入口始终位于游戏顶部。玩家可在任意非阻塞时刻打开设置、切换提供商、修改模型并执行连接测试。切换只影响下一次自由叙事请求，不重置当前游戏或记忆。

### Gemini 与 Groq 凭据模式

Gemini 和 Groq 各提供两种凭据模式：

1. **网站提供**：调用 Chronos 服务端的 `/api/game/ai`，使用 Render 环境变量中的 Key。
2. **自己的 Key**：保持原版 BYOK 行为，Key 只保存在当前浏览器的独立本地设置中并直接调用提供商。

服务端环境变量命名为：

- `GEMINI_API_KEY`
- `GEMINI_MODEL`，可选，缺省使用代码中当前稳定的 Flash 模型
- `GROQ_API_KEY`
- `GROQ_MODEL`，可选，缺省使用代码中受支持的通用指令模型

Puter、SiliconFlow、OpenRouter 和自定义接口保持各自原有的浏览器端连接方式。任何个人 Key 都不会经过 Chronos 服务端，也不会包含在游戏状态导出中。

## 服务端 AI 代理

`POST /api/game/ai` 只接受已登录的 Chronos 会话。请求包含提供商、规范化消息和可选模型；服务端只允许 `gemini` 或 `groq`，并忽略客户端传入的任意 URL。

服务端行为：

- 验证会话、请求大小、消息数量、单条长度和模型名称格式。
- 从环境变量读取 Key，并构造固定官方端点请求。
- 使用超时和有限重试处理临时错误。
- 以统一 `{ text, provider, model }` 格式返回结果。
- 不记录 Key、完整提示词或模型完整响应。
- 对每个登录账号执行内存级短窗口限流，防止单个账号快速耗尽免费额度。
- 上游限流、超时或未配置 Key 时返回明确错误码，前端提示后自动使用本地命运线完成当前回合。

服务重启会清空内存限流记录；这对单实例 Render 免费服务足够，避免为第一版引入额外基础设施。

## 状态与存档

游戏状态增加明确的 `schemaVersion`。自动存档、三个手动槽位和导出文件保存同一份经过清理的状态结构，包括：

- 玩家属性、境界、资源和装备
- 章节、地点、任务与事件旗标
- NPC 关系、因果和世界状态
- 成就、图鉴与已解锁结局
- AI 长期记忆摘要和有限关键事实

API Key、临时请求、AbortController、DOM 状态和当前网络错误不进入存档。

读取旧版 `luoying_save` 与三个旧槽位时执行迁移：补齐新字段、规范无效数值、保留原有人物关系和剧情旗标。迁移失败时不覆盖原始存档，并向玩家提供新开局或导出原数据的选择。

每个本地动作或成功 AI 回合后自动保存。手动槽位可以覆盖、读取和删除，并增加 JSON 导入导出，方便换设备或调试不同剧情线。

## 容错与安全

- AI 文本在进入 DOM 前按纯文本处理，不允许模型响应注入 HTML 或脚本。
- JSON 解析先尝试严格格式，再进行有限修复；不使用 `new Function` 执行模型文本。
- 所有外部调用均有超时、取消和可理解的中文错误提示。
- AI 失败只回退当前回合，不会永久改变玩家选择的提供商。
- 游戏在没有 Google Fonts、Puter 脚本或网络时仍能显示并使用系统字体与本地引擎。
- 导入存档有大小限制、结构验证和版本检查。

## 文件边界

独立游戏模块拆为职责清晰的文件：

- `index.html`：游戏语义结构、弹窗与资源入口。
- `styles.css`：保持原视觉并补充响应式、可访问性和新面板样式。
- `game-data.js`：境界、NPC、地点、物品、任务、章节和事件配置。
- `game-engine.js`：状态创建、迁移、规则、战斗、任务和本地剧情。
- `ai-client.js`：提供商设置、请求适配、结构化输出和回退。
- `storage.js`：自动存档、槽位、导入导出和设置存储。
- `app.js`：DOM 渲染、事件绑定、动画和各模块编排。

纯规则模块不依赖 DOM，便于用 Node 测试。模块之间通过明确的状态和动作对象交互，不共享隐藏的可变全局变量。

## 测试与验收

自动验证包括：

- 新状态结构、旧存档迁移和无效存档拒绝。
- 境界突破、任务推进、战斗胜负、奖励上限和多结局条件。
- AI 效果白名单、恶意文本转义、格式错误与回退。
- Groq/Gemini 服务端请求验证、缺少环境变量和上游错误映射。
- Chronos 生产构建成功。

浏览器冒烟验证包括：

- 登录后进入 `/chronos/game`，旧 Rift 页面已被替换。
- 新开局、自由输入、本地完整流程、自动保存与三槽读写可用。
- 游戏中切换本地、Gemini、Groq，并可在网站 Key 与个人 Key 间切换。
- AI 断网或限流后当前回合自动由本地引擎接管。
- 桌面与窄屏手机尺寸下无关键控件溢出，Chronos 导航仍可返回其他页面。

## 部署

代码推送到 `main` 后由现有 Render 配置构建。`render.yaml` 声明 Gemini/Groq 环境变量但不包含实际值；仓库 README 说明在 Render 控制台设置 Key 的方法。

未配置服务端 Key 时，游戏仍提供完整本地模式、Puter 和玩家自填 Key 模式。配置完成后，“网站提供”模式无需重新构建即可生效。
